# CNKI 学术定题服务系统 - 部署运维手册

**版本**：v1.1  
**日期**：2026-05-16

---

## 1. 系统概述

CNKI 学术定题服务系统采用前后端分离架构，项目为扁平结构（无 `backend/` 或 `frontend/` 子目录）：
- **后端**（`app/`）：FastAPI + SQLite（异步 aiosqlite）
- **前端**（`src/`）：React 18 + TypeScript + shadcn/ui（Vite 构建）
- **任务队列**：轻量级 SQLite 持久化队列（无外部中间件依赖）
- **浏览器自动化**：Camoufox + Playwright

## 3. 安装部署

> **架构说明**：项目为**扁平结构**，所有命令在**项目根目录**下执行。`.env` 文件在根目录，后端 Python 代码在 `app/`，前端代码在 `src/`。

### 3.1 Ubuntu / Linux 部署

```bash
# 1. 克隆项目
git clone <repo-url> sdi-cnki
cd sdi-cnki

# 2. 配置环境变量
# 编辑 .env（项目根目录），至少修改以下项：
#   JWT_SECRET_KEY=<随机密钥>
#   AES_ENCRYPTION_KEY=<随机32位密钥>
#   CNKI_USERNAME=<知网账号>
#   CNKI_PASSWORD=<知网密码>

# 3. 安装后端依赖 + Playwright 浏览器
pip install -r requirements.txt
playwright install chromium --with-deps   # Ubuntu 需要 --with-deps 安装系统依赖

# 4. 初始化数据库 + 管理员账户（自动建表、种子数据、管理员）
mkdir -p data
python -c "
import asyncio
from app.database import init_db, engine
from app.dependencies import hash_password
from sqlalchemy import text
async def s():
    await init_db()
    async with engine.begin() as c:
        await c.execute(text(\"INSERT OR IGNORE INTO users (username, password_hash, email, role, is_active) VALUES ('admin', :pw, 'admin@example.com', 'admin', 1)\"), {'pw': hash_password('admin123')})
    print('DB ready')
    await engine.dispose()
asyncio.run(s())
"

# 5. 启动 API 服务
python -m uvicorn app.main:app --reload --port 8000

# 6. 新终端 - 启动 Worker 进程（每种队列一个终端）
python worker_runner.py cnki 1      # CNKI 检索
python worker_runner.py llm 5       # LLM 分析（并发5）
python worker_runner.py download 1  # PDF 下载
python worker_runner.py export 2    # 导出打包（并发2）

# 7. 安装前端依赖并启动
npm install
npm run dev  # 端口 8848，/api 自动代理到 8000
```

## 4. 运维操作

### 4.1 启动/停止服务

**Ubuntu 后台运行（推荐 systemd 或 tmux）**：
```bash
# 后端 API
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# Worker 进程（后台运行）
mkdir -p logs
nohup python worker_runner.py cnki 1 > logs/worker-cnki.log 2>&1 &
nohup python worker_runner.py llm 5 > logs/worker-llm.log 2>&1 &
nohup python worker_runner.py download 1 > logs/worker-download.log 2>&1 &
nohup python worker_runner.py export 2 > logs/worker-export.log 2>&1 &
```

**Windows 运行**：每个进程需在独立终端窗口中执行：

| 进程 | 命令（新终端） |
|------|----------------|
| API 服务 | `python -m uvicorn app.main:app --reload --port 8000` |
| CNKI 检索 | `python worker_runner.py cnki 1` |
| LLM 分析 | `python worker_runner.py llm 5` |
| PDF 下载 | `python worker_runner.py download 1` |
| 导出打包 | `python worker_runner.py export 2` |

> **提示**：Windows 下可使用 `Start-Process -NoNewWindow -FilePath "python" -ArgumentList "worker_runner.py cnki 1"` 脚本化启动，或使用 `nssm` 注册为 Windows 服务。

### 4.2 进程管理

| 进程 | 队列 | 说明 | 并发数 |
|------|------|------|--------|
| `uvicorn` | — | FastAPI HTTP 服务 | 1 |
| `worker_runner.py cnki` | `cnki` | CNKI 检索（浏览器，串行） | 1 |
| `worker_runner.py llm` | `llm` | LLM 批量分析（API 调用） | 5 |
| `worker_runner.py download` | `download` | PDF 下载（浏览器，串行） | 1 |
| `worker_runner.py export` | `export` | 导出打包（文件操作） | 2 |

### 4.3 日志查看

日志统一输出到 stdout，JSON 格式：

```json
{"timestamp": "2026-05-15T10:00:00Z", "level": "INFO", "logger": "app.main", "message": "Starting up...", "request_id": "", "user_id": null}
```

各 Worker 日志包含队列类型和任务 ID，可用于监控：
- `Worker [cnki] picked task 42`
- `Worker [llm] progress: 45/120 analyzed, 2 failed`
- `Worker [download] completed: 12 success, 3 failed`

### 4.5 数据目录结构

```
data/
├── cnki_service.db          # SQLite 数据库
├── uploads/                 # CNKI 检索导出的 Excel
│   └── T{YYYYMMDD}{3位}/   # 按实例编号分组
├── downloads/               # 下载的 PDF
│   └── T{YYYYMMDD}{3位}/   # 按实例编号分组
├── exports/                 # 导出打包的 ZIP
│   └── export_T{...}.zip   # 导出文件（24h 过期）
└── cookies/                 # CNKI 浏览器 Cookie 持久化
```

### 4.6 数据备份策略

- **数据库**：每日自动备份（系统暂未内置定时备份，建议 crontab / 任务计划程序）
- **文件存储**：PDF 和导出 ZIP 位于 `data/` 目录，可通过 rsync / Robocopy 同步

**Ubuntu（crontab）**：
```bash
# 每日凌晨 3 点备份
0 3 * * * cp /path/to/sdi-cnki/data/cnki_service.db /backup/cnki_$(date +\%Y\%m\%d).db
# 保留最近 30 天
0 3 * * * find /backup/ -name "cnki_*.db" -mtime +30 -delete
```

**Windows（任务计划程序 + PowerShell）**：
```powershell
# 备份脚本 save-backup.ps1
Copy-Item "$env:USERPROFILE\sdi-cnki\data\cnki_service.db" "D:\backup\cnki_$(Get-Date -Format yyyyMMdd).db"
Get-ChildItem D:\backup\ -Filter "cnki_*.db" | Where-Object { $_.LastWriteTime -lt (Get-Date).AddDays(-30) } | Remove-Item
```

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `JWT_SECRET_KEY` | `change-me-to-a-random-secret-key` | JWT 签名密钥（**生产必须修改**） |

### 5.2 运行时配置（系统设置页面）

首次启动时系统自动在 `system_configs` 表中插入以下默认配置，管理员可在「系统配置」页面修改：

|--------|------|--------|
| `webhook_enterprise_wechat` | 企业微信群机器人 Webhook URL | 空（不启用） |
| `cnki_search_timeout` | CNKI 检索超时（秒） | 1800 |
| `llm_analysis_batch_size` | LLM 批量分析并发数 | 5 |
| `cnki_queue_concurrency` | CNKI 检索队列并发数 | 1 |
| `llm_queue_concurrency` | LLM 分析队列并发数 | 5 |
| `download_queue_concurrency` | PDF 下载队列并发数 | 1 |
| `export_queue_concurrency` | 导出打包队列并发数 | 1 |

### 6.2 磁盘空间监控

### 6.3 任务队列监控

直接在数据库中查询队列状态：

```bash
python -c "
import sqlite3
conn = sqlite3.connect('data/cnki_service.db')
cur = conn.execute('SELECT queue_type, status, COUNT(*) FROM task_queue GROUP BY queue_type, status')
for row in cur:
    print(f'{row[0]:12s} {row[1]:12s} {row[2]}')
"
```

示例输出：
```
cnki         pending        3
cnki         running        1
llm          completed     45
download     pending        2
```

- CNKI 检索完成
- LLM 分析完成
- PDF 下载完成
- 任务任意阶段失败

## 7. 常见故障处理

### 7.1 CNKI 登录失效

**症状**：Worker 日志中出现 "Login failed" 或 "Cookie expired"

**处理**：
1. 检查项目根目录 `.env` 中 `CNKI_USERNAME`/`CNKI_PASSWORD` 是否正确
2. 删除 `data/cookies/` 下的 Cookie 文件
3. 重启 CNKI Worker 进程

### 7.2 LLM API 调用失败

**症状**：LLM Worker 日志中出现 "API call failed"

**处理**：
1. 检查「大模型管理」页面中配置的 API Key 和端点是否正确
2. 确认网络可以访问 API 端点
3. 检查 LLM 配置的优先级顺序，系统会自动轮询下一优先级配置

### 7.3 磁盘空间不足

**症状**：日志中出现 "磁盘空间不足" 告警

**处理**：
1. 清理 `data/exports/` 中过期的 ZIP 文件
2. 清理 `data/downloads/` 中已完成任务的临时文件
3. 考虑增加磁盘或配置自动清理策略

### 7.4 PDF 下载失败

**症状**：下载状态显示 "失败" 或 "跳过"

**原因**：
- CNKI 无全文链接（跳过）
- 权限不足（403）
- 网络超时
- 所有三来源（哲舍科→万方→CNKI）均不可用

**处理**：在「任务实例结果页」查看详细错误信息，针对性地解决问题后重新下载。

## 8. 安全注意事项

1. **密钥管理**：`JWT_SECRET_KEY` 和 `AES_ENCRYPTION_KEY` 生产环境必须使用强随机字符串
2. **密码策略**：管理员账户创建后立即修改默认密码
3. **网络隔离**：API 服务不要直接暴露公网，建议通过 Nginx 反向代理
4. **访问控制**：仅管理员可管理用户和系统配置
5. **数据备份**：定期备份数据库和 PDF 文件

## 10. 卸载

**Ubuntu**：
```bash
# 停止所有进程
# 删除项目目录
rm -rf sdi-cnki/

# 如需清理数据，额外删除：
rm -rf ~/.cache/ms-playwright/  # Playwright 浏览器
```

```powershell
# 停止所有进程（在运行 API 和 Worker 的终端按 Ctrl+C）

# 如需清理 Playwright 浏览器缓存：
Remove-Item -Recurse -Force "$env:USERPROFILE\AppData\Local\ms-playwright"
```
