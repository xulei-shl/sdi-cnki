# CNKI 学术定题服务系统 - UI/UX 设计方案

**版本**：v1.0  
**日期**：2026-05-15  
**项目名称**：CNKI 学术定题服务系统

---

## 一、文档说明

### 1.1 目的

本文档定义 CNKI 学术定题服务系统的用户界面与交互体验设计方案，作为前端开发、UI 测试和用户体验验收的统一依据。

### 1.2 术语定义

| 术语 | 解释 |
|------|------|
| **三栏布局** | 左侧导航栏、中间列表区域、右侧详情面板的页面结构 |
| **详情面板** | 右侧固定宽度面板，展示选中数据的完整信息，不离开当前页 |
| **模态弹窗** | 居中弹出对话框，背景遮罩，需用户操作后关闭 |
| **确认对话框** | 小尺寸模态弹窗，用于操作前的二次确认 |
| **阶段指示器** | 横向步骤条，展示任务各阶段的完成状态 |
| **拖拽排序** | 通过拖拽手柄调整列表项排列顺序的交互方式 |
| **SSE 进度** | 通过 Server-Sent Events 实时推送的后端进度反馈 |
| **标签** | 用于展示状态、分类等信息的可视化标记组件 |

## 二、整体布局

### 2.1 页面框架

系统采用三栏布局，宽度分配如下：

| 区域 | 宽度 | 说明 |
|------|------|------|
| 左侧导航栏 | 240px | 功能切换 Tab + 二级菜单 |
| 中间列表区域 | 弹性（1fr） | 查询区域 + 分页表格 |
| 右侧详情面板 | 360px | 选中数据的详细展示，可收起 |

### 2.2 导航结构

左侧导航栏包含以下入口：

**普通用户视图：**
- 任务模板（默认）
- 任务实例

**管理员视图：**
- 任务模板（默认）
- 任务实例
- 设置（可折叠展开）
  - 用户管理
  - 大模型管理
  - 提示词管理
  - 系统配置

点击导航项切换中间列表区域内容，当前激活项高亮显示。

## 四、页面功能详述

### 4.1 任务模板管理页

#### 4.1.1 页面布局

中间列表区域 + 右侧详情面板。从属关系：任务模板 → 任务实例（一对多）。

#### 4.1.2 查询区域

位于中间区域顶部，包含：

- 关键词输入框：按任务名称模糊搜索
- 日期范围选择器：按创建时间筛选（开始日期 ~ 结束日期）
- 「检索」按钮：触发筛选
- 「新建」按钮：位于右侧，打开新建弹窗

#### 4.1.3 列表区域

**表格列定义：**

| 列名 | 说明 | 展示规则 |
|------|------|----------|
| 任务名称 | 字符串 | 超长截断显示省略号，hover 显示完整 |
| 描述 | 文本 | 最多显示 2 行，超长截断 |
| LLM 配置 | 字符串 | 显示关联的 LLM 配置名称列表 |
| 创建者 | 字符串 | 显示用户名 |
| 创建时间 | 时间 | 格式：YYYY-MM-DD HH:mm |
| 执行次数 | 数字 | 关联 task_instances 计数 |
| 状态 | 标签 | 启用=蓝色，禁用=灰色 |
| 最后执行时间 | 时间 | 格式：YYYY-MM-DD HH:mm，从未执行为「-」 |
| 操作 | 按钮组 | 详见 4.1.4 |

**排序规则**：默认按创建时间倒序排列。

#### 4.1.4 操作按钮

| 按钮 | 可见条件 | 行为 |
|------|----------|------|
| 详情 | 始终可见 | 右侧面板展示详情 |
| 编辑 | 自己的模板 / 管理员 | 弹出编辑窗口 |
| 运行 | 始终可见 | 弹出运行确认弹窗 |
| 删除 | 仅无关联实例时可删除 | 确认后软删除；有实例则隐藏按钮 |

##### 运行确认弹窗

弹窗说明文本：「将基于此模板创建新的任务实例并执行。」

三个操作按钮：
| 按钮 | 行为 |
|------|------|
| 直接运行 | 创建任务实例 → 自动加入执行队列 → 跳转到任务实例列表页 |
| 确认后运行 | 创建任务实例 → 停留在任务实例页（手动点击运行）→ 跳转到任务实例列表页 |
| 取消 | 关闭弹窗，不进行任何操作 |

**注意**：「确认后运行」创建的实例在任务实例页有「编辑」和「运行」按钮；「直接运行」创建的实例无这两个按钮。

#### 4.1.5 新建/编辑弹窗

**弹窗尺寸**：宽度 800px，高度自适应，超出滚动。

**字段分组展示：**

**分组一：基础信息**
| 字段 | 组件类型 | 必填 | 校验规则 |
|------|----------|------|----------|
| 任务名称 | Input | 是 | 最多 200 字 |
| 任务描述 | Textarea | 否 | — |

**分组二：CNKI 检索参数**
| 字段 | 组件类型 | 必填 | 说明 |
|------|----------|------|------|
| 检索词 | Input | 是 | 实际执行两条条件：主题=query OR 篇关摘=query |
| 起始年份 | InputNumber | 否 | 与更新范围互斥 |
| 结束年份 | InputNumber | 否 | 与更新范围互斥 |
| 更新范围 | Select | 否 | 选项：一周/一月/半年/一年/今年初/去年；与年份范围互斥 |
| 仅核心来源 | Checkbox | 否 | 勾选后显示具体来源多选（WJCI/SCI/EI/北大核心/CSSCI/CSCD/AMI） |
| 同义词扩展 | Checkbox | 否 | — |
| 包含无全文 | Checkbox | 否 | 默认不勾选（仅看有全文） |
| 导出上限 | InputNumber | 否 | 默认 500 |

**分组三：LLM 分析配置**
| 字段 | 组件类型 | 必填 | 说明 |
|------|----------|------|------|
| LLM 配置优先级 | 多选拖拽组件 | 是 | 从已启用的列表中选择，拖拽调整优先级，至少选 1 个 |
| 提示词模板 | Select | 否 | 从已启用的提示词列表中选择 |

**底部按钮**：保存 / 关闭。

**编辑模式**：字段预填当前值，修改后仅影响后续新建的实例，已执行的历史实例不受影响。

#### 4.1.6 右侧详情面板

点击某行后展示：

- **基本信息**：名称、描述、创建者、创建时间、最后执行时间
- **检索参数卡片**：检索词、年份范围/更新范围、核心期刊、同义词扩展等
- **LLM 分析配置**：按优先级顺序展示已关联的配置列表
- **提示词模板**：名称（如有）
- **执行历史**：该模板下最近 5 条任务实例的简易列表（实例编号 + 状态 + 创建时间），点击任一跳转到任务实例管理页

### 4.2 任务实例管理页

#### 4.2.1 页面布局

与任务模板管理页一致的三栏布局。

#### 4.2.2 查询区域

- 实例名称关键词检索
- 关联模板名称关键词检索
- 创建日期范围筛选
- 「检索」按钮

#### 4.2.3 列表区域

**表格列定义：**
| 列名 | 说明 | 展示规则 |
|------|------|----------|
| 实例编号 | 字符串 | 格式：T{YYYYMMDD}{3位序列号} |
| 关联模板 | 字符串 | 对应的 meta_task 名称 |
| 状态 | 标签 | 颜色编码见 4.2.5 |
| 创建者 | 字符串 | 执行用户 |
| 创建时间 | 时间 | YYYY-MM-DD HH:mm |
| 数据统计 | 字符串 | 格式：有效数/总数（去重重复数） |
| 操作 | 按钮组 | 详见 4.2.4 |

#### 4.2.4 操作按钮

| 按钮 | 可用条件 | 行为 |
|------|----------|------|
| 详情 | 始终可见 | 右侧面板展示详情 |
| 编辑 | 仅 `pending` 状态的实例 | 弹出编辑窗口，可修改 execution_params |
| 运行 | 仅 `pending` 状态且通过「确认后运行」创建的实例 | 弹出确认弹窗，确认后加入队列 |
| 查看 | 始终可见 | 跳转到任务实例结果页（独立路由） |
| 下载 | 状态为 `completed` | 打包下载 ZIP |

**注意**：编辑和运行按钮在任务开始执行后（非 `pending`）消失或置灰。

#### 4.2.5 阶段状态指示器

列表行或详情面板中展示横向步骤条：

| 前端展示 | 对应 status | 颜色 |
|----------|-------------|------|
| ① 待执行 | `pending` | 灰色 |
| ② 检索中 | `running` | 蓝色 + 加载动画 |
| ③ 分析中 | `analyzing` | 蓝色 + 加载动画 |
| ④ 审核中 | `analyzing_completed` | 蓝色（静态，等待人工操作） |
| ⑤ 等待下载 | `ready_for_download` | 蓝色（静态，已入队等待 worker 调度）|
| ⑥ 下载中 | `downloading` | 蓝色 + 加载动画 |
| ⑦ 已完成 | `completed` | 绿色 |

**⑤ 等待下载说明**：用户点击「开始下载」后，实例先进入 `ready_for_download`（已排队但尚未被 worker 取走），download worker 取走后才变为 `downloading`。此状态需在前端正常展示，不可静默忽略。

**异常状态**：
| 展示 | 对应 status | 颜色 |
|------|-------------|------|
| ❌ 失败 | `failed` | 红色，步骤中断，显示错误信息 |
| ⏸ 已取消 | `cancelled` | 灰色 |

每个步骤下方显示对应阶段的实际发生时间戳（如：2026-05-14 10:30），字段来源：

| 步骤 | 时间戳字段 |
|------|------------|
| 检索完成 | `task_instances.search_completed_at` |
| 分析完成 | `task_instances.analysis_completed_at` |
| 开始下载 | `task_instances.download_started_at` |
| 全部完成 | `task_instances.completed_at` |

### 4.3 任务实例结果页（独立路由）

#### 4.3.1 页面布局

独立路由页面，非三栏布局：

```
┌──────────────────────────────────────────────────────────────────┐
│  返回按钮 | 实例编号 - 关联模板名称                                │
├──────────────────────────────────────────────────────────────────┤
│  [阶段指示器：待执行 → 检索中 → 分析中 → 审核中 → 下载中 → 完成]  │
├──────────────────────────────────────────────────────────────────┤
│  批量操作栏：全部通过 | 全部拒绝 | 重新分析 | 下载 | 导出 Excel   │
├──────────────────────────────────────────────────────────────────┤
│  筛选栏：审核状态 | 分析状态 | 期刊 | 年份 | 评分 | 含重复项 ☐  │
├──────────────────────────────────────────────────────────────────┤
│  ┌──────────────────────────────────────────────────┐ ┌─────────┐│
│  │  列表区域（选择框 | 题名 | 作者 | 期刊 | 相关性  │  │ 详情面板 ││
│  │  | 分析状态 | 审核状态 | 下载状态 | 操作）       │  │ (点击行  ││
│  │                                                  │  │  后展示) ││
│  └──────────────────────────────────────────────────┘ └─────────┘│
├──────────────────────────────────────────────────────────────────┤
│  分页控件                                                     │
└──────────────────────────────────────────────────────────────────┘
```

#### 4.3.2 筛选条件

| 筛选维度 | 组件 | 选项 |
|----------|------|------|
| 审核状态 | Select | 全部 / 待审核 / 已通过 / 已拒绝 |
| 分析状态 | Select | 全部 / 已完成 / 未分析 / 失败 |
| 期刊名称 | Input | 模糊搜索 |
| 出版年份 | InputNumber | 精确年份 |
| 相关性评分 | Select | 范围选项：≥4 / ≥6 / ≥8 / ≥9（对应 0-10 分段）|
| 含重复项 | Checkbox | 默认不勾选，勾选后显示 `is_duplicate = true` 的记录 |

#### 4.3.3 列表区域

| 列名 | 说明 | 展示规则 |
|------|------|----------|
| 选择框 | Checkbox | 用于批量操作 |
| 题名 | 文本 | 超长截断，hover 显示完整；重复项添加橙色「重复」标签 |
| 作者 | 文本 | 最多显示 3 人，超出显示「等」 |
| 期刊 | 文本 | 期刊名称 + 年份 |
| 相关性 | 进度条 + 数字 | 展示 0-10 整数原始分，进度条宽度按 `score/10` 换算；颜色：≤3 灰 / 4-6 蓝 / ≥7 绿 |
| 分析状态 | 标签 | 已完成（绿）/ 进行中（蓝）/ 失败（红） |
| 审核状态 | 标签 | 通过（绿）/ 拒绝（红）/ 未审（灰） |
| 下载状态 | 标签 | 已完成（绿）/ 下载中（蓝）/ 失败（红）/ 未下载（灰）/ 跳过（橙） |
| 操作 | 按钮 | 详情 / 通过 / 拒绝 |

#### 4.3.4 批量操作栏

| 操作 | 行为 | 前置条件 |
|------|------|----------|
| 全部通过 | 所有非重复、待审核记录 `is_passed = 1` | 弹出确认框 |
| 全部拒绝 | 所有非重复、待审核记录 `is_passed = 0` | 弹出确认框 |
| 重新分析 | 所有分析状态为 failed 的记录重新触发 LLM 分析 | 弹出确认框 |
| 下载 | 将 `is_passed = 1` 且未下载的记录加入下载队列 | 状态需 `analyzing_completed` 以上 |
| 导出 Excel | 导出选中记录 | 至少选中 1 条 |

**下载进度展示**：
- 下载过程中按钮区域显示 SSE 实时进度：`成功: 12, 失败: 3, 总计: 15`
- 全部完成后显示「打包下载 ZIP」按钮

#### 4.3.5 单条审核操作

- **通过**：点击即更新 `is_passed = 1`，标签即时刷新
- **拒绝**：点击即更新 `is_passed = 0`，标签即时刷新
- **取消审核**：已通过的再点击「通过」可取消，已拒绝的再点击「拒绝」可取消

#### 4.3.6 右侧详情面板

点击某行后按分组展示：

**分组一：文献信息（只读）**
题名 / 作者（全部）/ 作者单位 / 期刊 / 发表时间 / 卷期页码 / 关键词 / 摘要（可展开）/ DOI / 中图分类号 / 基金 / 参考格式

**分组二：LLM 分析结果**
- 动态渲染为键值对表格（字段名 → 值）
- 枚举值以标签样式高亮（如 `relevance_level` → High/Medium/Low/Irrelevant）
- 分析状态 + 错误详情（如有）
- 「重新分析」按钮（仅 failed 状态可点击）

**分组三：下载信息**
下载状态 / PDF 路径 / 文件大小 / 错误信息（失败时）

## 五、交互设计规范

### 5.1 模态弹窗规范

| 场景 | 宽度 | 说明 |
|------|------|------|

### 6.6 SSE 实时推送规范

**连接建立**：进入任务实例结果页后，若实例状态不为 `completed` / `failed` / `cancelled`，前端立即建立 SSE 连接：

```
GET /api/v1/tasks/{instance_id}/events
Authorization: Bearer {token}
```

**断线重连策略**：
- 浏览器原生 `EventSource` 支持自动重连（默认 3 秒），但**不携带 JWT**，需改用手动实现：
  - 使用 `fetch` + `ReadableStream` 或封装库（如 `@microsoft/fetch-event-source`）发起 SSE 请求，携带 `Authorization` 头
  - 连接断开后，指数退避重连：1s → 2s → 4s → 8s，最大间隔 30s
  - 重连时携带 `Last-Event-ID` 请求头，后端可选择从该事件后续发送（防止漏事件）

**心跳**：后端每 15 秒推送一次 `event: ping`，前端忽略 ping 事件，仅用于保活连接

**事件格式**：

```
event: task.progress
data: {"status": "analyzing", "analyzed": 45, "total": 120, "failed": 2}

event: download.progress
data: {"success": 12, "failed": 3, "skipped": 1, "total": 15}

event: task.completed
data: {"status": "completed", "completed_at": "2026-05-15T10:30:00"}

event: task.failed
data: {"status": "failed", "error_message": "CNKI 登录会话已过期"}

event: ping
data: {}
```

**前端处理**：
- 收到 `task.completed` / `task.failed` / `task.cancelled` 后，关闭连接，刷新页面数据
- 连接建立后立即请求一次 `GET /api/v1/task-instances/{id}` 同步当前状态，防止页面加载时错过已完成的事件

## 七、前端实现规范 (基于 pure-admin-thin)

本项目前端严格复用 [vue-pure-admin 官方精简版 (非国际化)](https://github.com/pure-admin/pure-admin-thin) 的底层架构。开发时必须遵循以下规范：

### 7.1 目录结构与代码组织规范

*   `src/api`：存放所有与后端的接口请求协议，不得在 components 内部直接写 fetch/axios 调用。
*   `src/views`：页面级组件，根据路由结构建立文件夹。
*   `src/router`：利用纯动态路由功能。`router.beforeEach` 进行 Token 拦截并从后端拉取菜单构建用户专属侧边栏。
*   `src/store`：使用 Pinia 进行状态管理，包含用户信息、已授权 `role` 列表和 tags-view。

### 7.2 路由与权限 (RBAC)

*   **动态路由**：普通用户登录后只渲染具备权限的模块（如：隔离"系统设置"模块）。
*   **路由元数据 (`meta`)**：通过 `meta.roles` 配置对应路由权限标识。后端根据用户权限返回对应的路由数据表并由 `router.addRoute` 挂载。
*   **细粒度按钮权限**：采用自定义指令 `v-auth="['admin']"` 控制具体按钮的显隐，无需重复造轮子，直接利用框架提供的 `hasAuth` 辅助函数。

### 7.3 API 请求配置与 JWT 刷新

复用 `pure-admin-thin` 的极简封装：
*   **请求库集成**：所有网络请求要求统一通过 `src/utils/http/index.ts` 中封装的 `pureHttp` 调用。
*   **双 Token 刷新（无感刷新）**：利用 Axios `response` 拦截器处理 `401 Unauthorized`：
    1.  处于 `isRefreshing` 时将其他接口请求推入缓存队列。
    2.  携带 `refresh_token` 请求后端颁发新的 `access_token`。
    3.  替换本地存储 `access_token` 并重放队列。若刷新均失败，则重置所有前端缓存，跳转 `/login`。

### 7.4 其他约定

*   **非国际化（No i18n）**：使用无 `vue-i18n` 版本。代码中各类静态提示、`el-message` 等直接硬编码全中文（如："操作成功"）。
*   **样式约定**：支持 Tailwind CSS 工具类加速布局，尽量避免写全局未加 SCOPE 的深层 CSS。组件采用框架封装成熟的 `el-dialog` 与 PureAdmin 自带容器，无特殊要求不自己发明全局组件库。
