## 4. 根因分析

### 4.1 导出队列状态泄漏（系统性问题，8 次复现）✅ 已定位代码

**根因**：`app/worker/export_worker.py` 的 `run_export()` **从未调用 `svc.complete(task_item_id, ...)`**。

- `run_export(db, task_item_id, params_json)` 接收了 `task_item_id` 参数，但函数体内只更新了 `export_task`（`export_tasks` 表）的状态为 `completed` 并广播 SSE，**漏掉了对 `task_queue` 行的完成标记**。
- 对比正常实现：
  - `cnki_worker.py`：`await svc.complete(item_id, ...)` ✅
  - `download_worker.py`：`await svc.complete(item_id, ...)` ✅
  - `export_worker.py`：❌ 缺失
- 后果：`task_queue` 行永远停留在 `running`，即使 ZIP 已生成、`export_tasks.status = completed`。Worker 只拾取 `pending` 任务，这些残留行永远不会被重新处理，只能靠手动清理。
- 复现记录：5-7 月累计 8 次导出全部如此（qid 4/7/9/10/17/24/36/42）。

**修复建议**：在 `run_export` 成功分支末尾加 `await svc.complete(task_item_id, json.dumps({...}))`；异常分支（已 `raise` 由队列框架处理）保持 `svc.fail` 语义或显式调用。需注意与现有重试机制的配合。

### 4.2 下载任务卡死（T20260801001）⚠️ 需人工确认

- `download_T20260801001` 自 2026-08-01 12:01:40 起处于 running，已 ~2 天。
- 该实例 400 条 `task_results` 的 LLM 分析全部完成，但 `download_results` 仅 20 条（**18 completed + 2 failed**），即只处理了约 5%。
- 当前 `download_worker.py` 的筛选条件是 `is_duplicate == False AND is_passed == True`，而该实例 400 条 `is_passed` **全部为 NULL** —— 与已产生 18 条下载成功记录存在矛盾，推测 08-01 触发下载时这些记录曾被标记通过（或当时逻辑不同），之后状态被改动，**需人工确认**。
- 2026-08-03 09:15 后端重启后，该任务的内存执行态已丢失，且队列行仍为 running（Worker 不会重新拾取），**实例将永久停留在"下载中"**。

**恢复建议**（见第 5 节）：先人工确认/设置 `is_passed`，重置队列行后重新触发下载。

### 4.3 孤儿任务（export_T20260528004_7）

- 指向实例 T20260528004，该实例已从 `task_instances` 删除（id 6/7 区间），但导出队列行未被级联清理（删除实例时队列取消逻辑可能未覆盖该场景，或删除发生在任务入队后）。
- 纯孤儿，直接清理即可。

## 7. 交接注意事项

1. **队列状态 ≠ 实例状态**：`task_queue.status` 与 `task_instances.status` 是两个独立的状态机。实例已完成 ≠ 队列行已清理；Worker 只处理 `pending` 行，`running` 残留行不会被自动回收。
2. **导出 ZIP 是有效产物**：即使队列行显示 running，只要 `export_tasks.status = completed` 且文件存在，导出结果就是有效的，可放心清理队列行。
3. **下载卡死无自动恢复**：download 任务卡死后必须手动重置队列行 + 重新触发，否则实例停在"下载中"。
4. **相关代码**：
   - `app/worker/export_worker.py`（导出泄漏根因，待修复）
   - `app/worker/download_worker.py`（下载执行逻辑）
   - `app/task_queue/crud.py`（TaskQueueService：complete/fail/retry_failed）
5. **本次调查未执行任何数据变更**，所有结论基于只读查询；生产库 `data/cnki_service.db` 建议定期备份。
