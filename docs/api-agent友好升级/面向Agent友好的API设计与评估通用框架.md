### 一、 核心痛点与思维模型转变

| 维度 | 传统 API（面向 Web / 离线脚本） | 现代 Agent API（面向大模型 / 智能体） |
| :--- | :--- | :--- |
| **消费者特征** | 浏览器渲染、离线批处理脚本；内存大、无上下文上限 | **有限上下文窗口（Tokens 昂贵）**、存在“大海捞针”注意力衰减 |
| **执行环境** | HTTP 客户端、后台服务 | **Subprocess / CLI Runner**；标准流（stdout）通常限 40~64KB，超限直接硬截断导致 JSON 解析崩溃 |
| **数据理解** | 按字段硬编码渲染 | **依靠语义自适应理解**；冗余/内部状态字段极易诱发大模型**负面幻觉与误判** |
| **消费目标** | 单次把所有明细展示给人类用户 | **“快速理解决策”与“全量数据沉淀”往往并存且分流** |

### 二、 核心优化原则（评估类似 API 的 4 大法则）

#### 原则 1：双轨分离法则（轻量感知 vs 全量留存）
* **核心逻辑**：**大模型感知不需要全量数据，全量数据不需要塞进 Prompt。**
* **落地模式**：
  1. **感知轨（Perception Track）**：通过 **稀疏字段集（Field Masking）** + **低条数分页（`limit`）**，仅向大模型注入决策必需的核心字段（如 `fields=core&limit=10`）。
     * *效果*：体积从 150KB 锐减至 3KB，Token 消耗下降 95%，彻底杜绝管道截断与上下文污染。
  2. **留存轨（Retention Track）**：全量稠密数据（含长文本摘要、机构、基金等）**沉淀为静态文件**（带短期签名的直链），大模型仅需持有文件 URL 或本地路径，供用户下载或向量库离线精读。

#### 原则 2：契约通用法则（API 提供原子积木，Agent 负责拼装）
* **核心逻辑**：**严禁在服务端 API 硬编码 Agent 场景的业务特例**（例如不能在 API 侧写死“强制前 10 条返回 JSON，其余存文件”）。
* **落地模式**：
  * **API 侧（提供标准化基础能力）**：
    * 提供字段裁剪：`fields=core` 或 `fields=title,authors`；
    * 提供静态文件下载：`format=json_file` 或 `format=excel`。
  * **Agent / Skill 脚本侧（负责编排业务流程）**：
    * 脚本先调 `limit=10&fields=core` 取得轻量预览喂给模型；
    * 同时静默调用静态文件直链并落盘到本地，把文件路径挂载给模型。
  * *收益*：API 保持标准 RESTful 规范，兼顾爬虫、前端与 Agent 等多方调用者。

#### 原则 3：语义纯净与防幻觉法则（剥离平台内部状态字段）
* **核心逻辑**：**输出给 LLM 的数据必须是业务实体的客观属性，严禁暴露系统内部的有状态标记。**
* **本次典型教训（`is_duplicate`）**：
  * `is_duplicate` 属于本系统内部定题监控（SDI）的历史轮次对比标记，不属于文献客观元数据。
  * 若将其暴露给一次性即时调用的 Agent，大模型极易产生**严重幻觉**（误以为本次检索结果列表内部有重复，从而在研报中擅自过滤有用文献）。
* **评估标准**：自查响应体中是否存在内部调度状态（如去重标记、内部外键 ID、审核轮次、锁标记等），面向 Agent 的视图应坚决剥离。

#### 原则 4：懒生成与缓存代理法则（按需计算，避免 I/O 放大）
* **核心逻辑**：**不改变主链路性能，在边缘按需衍生制品。**
* **落地模式**：
  * 检索完成时不主动生成大 JSON 文件（避免无用磁盘 I/O 放大）；
  * 仅当调用方真正请求 `format=json_file` 或下载直链时，触发“按需生成 + 磁盘文件缓存（Cache-Aside）”。

### 三、 类似 API 评估自查清单（Checklist）

在后续评估其他系统的搜索、列表、导出等 API 时，可直接使用以下 5 项检查清单：

```markdown
- [ ] 1. 缓冲区安全：单次最大默认返回（如 50~100 条）的 JSON 体积是否小于 30KB？（是否可能撑爆 CLI stdout 缓冲区导致截断？）
- [ ] 2. 字段稠密度：是否包含文章摘要（abstract）、评论全文、HTML/Markdown 等长文本字段？是否支持字段裁剪（fields=core）？
- [ ] 3. 消费双轨制：是否提供结构化静态文件直链（如 format=json_file / format=excel），使 Agent 能零 Token 负担沉淀全量数据？
- [ ] 4. 字段纯净度：是否存在类似 is_duplicate、internal_status、deleted_flag 等内部状态字段可能诱发模型幻觉？
- [ ] 5. 契约边界：API 是否保持了正交通用？（未将 Agent 的私有交互习惯硬编码进服务端逻辑）
```
