# 开发变更记录：开放接口 v1（agent 检索元数据）

- **日期**: 2026-09-29

> **后续调整（2026-09-30）**：本文第 6.1 节的优先级策略已反转——API 作业改为 `priority=-1`（高于网页任务的 `0`），由 API 优先出队。详见 `20260930_开放接口队列优先级调整.md`。

## 1. 变更摘要

把既有「CNKI 检索 → 导出元数据 Excel → 解析入库」链路封装为面向 agent / 第三方系统的开放接口，
只覆盖**检索与元数据**，不触发 LLM 分析与 PDF 下载。

接口前缀 `/api/v1/open`，以 API Key 鉴权，采用「提交即返回 + 可长轮询的状态查询 + JSON 结果」。

## 2. 为什么不是同步接口

单次检索由浏览器自动化完成（登录校验、等结果页、分批导出），典型耗时 1~3 分钟，同步接口必然超时。
因此：

- `POST /metadata-jobs` 只做校验与入队，立即 202 返回；
- 状态查询 `GET /metadata-jobs/{id}` 永不阻塞、结构稳定；
- 支持 `?wait=N`（N≤25）长轮询：状态一变立即返回，到点返回当前状态。

## 3. 进度语义：阶段 + 心跳，而不是百分比

检索过程中真正耗时的是不可分割的浏览器步骤，
且 `EXPORT_BATCH_SIZE=500` 而导出上限仅 50/100，**永远只有 1 个批次**，
因此批次级百分比没有意义。改为：

- `stage` + `stage_message`：来自 `ProfessionalCnkiInteractor.execute_search` 的阶段回调
  （`launching` → `navigating` → `authenticating` → `searching` → `submitting` → `waiting_results`
  → `collecting` → `exporting` → `merging` → `parsing` → `done`）；
- `heartbeat_age_seconds`：由独立心跳任务每 5s 刷新，**与浏览器步骤解耦**。
  即便 `waiting_results` 卡 90s，心跳仍在走，调用方据此区分「耗时长」与「卡死」；
- `eta_seconds`：仅当存在历史 API 作业时按最近 10 次均值估算，否则为 `null`（不猜测）。

阶段回调与心跳由 `cnki_worker._save_progress` / `_heartbeat_loop` 写入 `task_instances`，
因此**跨进程可见**（网页进程与独立 worker 进程部署均可用，不依赖进程内内存）。

## 4. 数量参数

- 默认 50（沿用 `execute_search` 与前端既有默认值）；
- 上限固定 100，通过 `Literal[50, 100]` 约束，非法取值直接 422；
- `export_limit = min(total, max_export)`，命中不足时返回条数会少于请求数，
  响应同时给出 `counts.total/valid/duplicate`。网页端仍保持 `{50,100,...,500}` 不变。

## 5. 结果返回：JSON 为主，Excel 为辅

| 形式 | 端点 | 说明 |
|------|------|------|
| JSON（默认） | `GET /metadata-jobs/{id}/results?format=json` | 分页返回结构化元数据（19 字段），agent 可直接消费，无需解析 xlsx |
| Excel 下载地址 | `GET /metadata-jobs/{id}/results?format=excel` | 返回短期签名 `download_url`（默认 30 分钟）与 `expires_at`，不占用 JSON 体积 |
| Excel 内联 | `...&format=excel&inline=true` | 直接返回文件；超过 5MB 返回 413 并提示改用 `download_url` |
| 文件本身 | `GET /metadata-jobs/{id}/artifact?token=...` | 签名令牌可脱离 API Key 使用，便于交给浏览器/用户落地文件 |

## 6. 串行队列与网页隔离

### 6.1 与网页用户的关系

- API 与网页触发的是**同一个 `cnki` 队列**（并发=1），且共用同一 CNKI 账号与
  `data/cookies/cnki_cookies.json`，二者天然串行，不会互相踢登录态或并触发验证码；
- 代价是**互相排队**：API 任务会延长网页检索的排队时间。
  因此 API 任务 `priority=10`，网页任务 `priority=0`，
  `dequeue` 按 `priority ASC, created_at ASC` 取任务 → **网页请求优先出队**；
- API 作业 `source='api'`，不在网页实例列表、元任务列表与 `/system/stats` 中展示；
  也不发送企微/邮件通知、不广播 SSE（网页列表页不会出现该作业）。

### 6.2 内部载体

`TaskInstance.meta_task_id` 与 `creator_id` 均为非空，故接口自动创建（幂等）：

- 服务账号 `api_service`（`is_active=False`，随机密码，不可登录）；
- 隐藏模板 `开放接口检索（内部）`（`source='api'`、`is_active=False`）。

## 8. 接口一览

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | `/api/v1/open/keys` | 管理员 JWT | 创建 API Key，明文仅返回一次 |
| GET | `/api/v1/open/keys` | 管理员 JWT | 列出 Key（不含明文） |
| DELETE | `/api/v1/open/keys/{id}` | 管理员 JWT | 停用 Key |
| POST | `/api/v1/open/metadata-jobs` | API Key | 提交检索作业（支持 `idempotency_key`） |
| GET | `/api/v1/open/metadata-jobs/{id}` | API Key | 状态查询，支持 `?wait=N` 长轮询 |
| GET | `/api/v1/open/metadata-jobs/{id}/results` | API Key | `format=json|excel`、`inline` |
| GET | `/api/v1/open/metadata-jobs/{id}/artifact` | 签名 token 或 API Key | 下载原始元数据 Excel |

## 10. 风险与注意事项

- **单账号瓶颈**：无论多少调用方，CNKI 检索吞吐上限仍是一次一篇，接口必须按 key 配额与背压使用。
- **验证码**：`wait_for_captcha_completion` 需要人工介入，无人值守场景下验证码出现即作业失败。
- **去重作用域**：API 作业共用同一个隐藏模板，因此后续 API 作业会把与之前作业重复的文献标为
  `is_duplicate`，`counts.valid` 会低于 `counts.total`。若需要每次返回全量，需为 API 作业关闭去重
  或按调用方隔离模板。
- **管理员仍可通过 id 直接访问**：隔离作用于列表与统计；管理员若已知实例 id，详情接口仍可打开。
- 合规：自动化批量导出元数据受 CNKI 服务条款约束，对外开放会放大该风险。
