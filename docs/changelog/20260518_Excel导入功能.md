# 任务实例结果页 Excel 导入功能

**日期**：2026-05-18

## 变更概要

为「确认后运行」创建的待执行任务实例新增 Excel 导入功能，使其结果数据既可来自 CNKI 检索，也可来自用户上传的本地文件。

## 修改文件

| 文件 | 变更类型 | 说明 |
|------|----------|------|
| `app/routers/task_instances.py` | 新增 | `POST /{instance_id}/import-excel` 端点 |
| `app/services/excel_parser.py` | 修改 | `_read_raw_data()` 多格式解析支持 |
| `src/api/task-instances.ts` | 新增 | `importExcelResults()` API 函数 |
| `src/pages/task-result/index.tsx` | 修改 | pending + auto_run=false 时显示上传区 |

## 功能行为

### 数据流

```
用户上传 .xlsx/.xls/.csv
    │
    ▼
_read_raw_data()   →   自动检测格式并解析
    │
    ▼
batch_check_and_mark()   →   查重 + 标记
    │
    ▼
批量插入 task_results 表
    │
    ▼
instance.status = search_completed
(跳过 search_queued / running)
    │
    ▼
(auto) 入队 LLM 分析 (valid > 0 且 ≤ 2000)
    │
    ▼
analyzing → analyzing_completed → download → completed
```

### 状态流转

**导入前**：`pending` (auto_run=false, 未执行)
**导入后**：`search_completed` (直接跳转，无需浏览器检索)

### 页面行为

| 场景 | 显示内容 | 说明 |
|------|----------|------|
| pending + auto_run=false | Excel 上传区 | 替换筛选栏 + 表格 |
| 其他状态 | 筛选栏 + 表格 | 与原行为一致 |
| 导入成功后 | 自动刷新为表格视图 | 阶段指示器跳转至 search_completed |
| 导入失败 | 上传区保留 + 错误提示 | 保留已选文件，可重试 |

### 任务实例列表页联动

| 场景 | 运行按钮 | 编辑按钮 | 删除按钮 |
|------|----------|----------|----------|
| 上传前 (pending) | 显示 | 显示 | 显示 |
| 上传后 (search_completed) | 隐藏 | 隐藏 | 隐藏 |

## 支持的文件格式

| 格式 | 解析策略 | 说明 |
|------|----------|------|
| `.xlsx` | `pd.read_excel(engine="openpyxl")` | 标准 Excel 格式 |
| `.xls` | 先尝试 `openpyxl`，失败后 `pd.read_html()` | 兼容 CNKI 导出的 HTML 假 xls |
| `.csv` | `pd.read_csv(encoding="utf-8"/"gbk"/"gb2312")` | 自动尝试常用编码 |

## 异常处理

| 场景 | HTTP | 提示信息 |
|------|------|----------|
| 状态不是 pending | 400 | 任务实例状态不允许导入，当前状态：{status} |
| auto_run=true 的实例 | 400 | 仅「确认后运行」创建的实例支持 Excel 导入 |
| 文件扩展名不符合 | 400 | 仅支持 .xlsx、.xls、.csv 格式的文件 |
| 文件无法读取/损坏 | 400 | 文件无法读取，请确认是有效的 Excel 文件 |
| 未识别到 CNKI 列 | 400 | 未解析到有效数据，请确认上传的是 CNKI 导出的 Excel 文件 |
| 数据行超过 500 | 400 | 数据行数超过上限（最多 500 条），当前 {n} 条 |
| 全部重复 | 200 (成功) | 正常响应，valid=0 不触发 LLM 分析 |
| 写入数据库失败 | 500 | 导入失败，请重试 |

## 设计要点

1. **复用现有解析链路**：`parse_excel_to_records()` + `batch_check_and_mark()` 完全复用 CNKI 检索流程
2. **KISS 原则**：不做中间状态 `importing`，失败自动回滚保持 `pending`
3. **格式抽象**：新增 `_read_raw_data()` 层将格式检测与业务逻辑隔离，后续扩展格式只改此函数
4. **前端无侵入**：上传区仅在 pending+auto_run=false 时显示，不影响其他状态的正常功能
5. **文件名安全**：使用 `Path(file.filename).name` 防止路径穿越
