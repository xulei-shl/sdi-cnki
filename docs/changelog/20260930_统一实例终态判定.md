# 开发变更记录：统一实例终态判定

- **日期**: 2026-09-30

## 1. 变更摘要

把实例「是否已终态」的判定收敛到 `resolve_review_status` 一处，
`download_worker` 的 5 个状态决策分支全部改用它。**状态不再取决于用户点了几次下载。**

## 2. 为什么统一：不是重复，而是两处判定会互相矛盾

前置修复（`20260930_修复已完成实例被打回审核中.md`）只改了 `llm_worker`。
当时判断 `download_worker` 的同类内联判定「已是数据派生、不必动」，**这个判断不完整**。

`download_worker` 有 5 个状态决策，与统一判定的对照如下：

| 分支 | 原有行为 | 统一判定 | 结论 |
|------|----------|----------|------|
| 无有效数据 | `completed` | 需补规则 | 已补：无有效数据 → `completed` |
| 有数据但零审核通过 | `analyzing_completed` | 一致 | ✓ |
| 审核通过全部下载成功 | `completed` | 一致 | ✓ |
| 重跑时无待下载记录且有失败 | `analyzing_completed` | 一致 | ✓ |
| **批量刚跑完（含失败）** | **`completed`** | **不一致** | **本次修正** |

最后一行是真正的漂移：**同一份数据（部分记录失败），在“批量刚跑完”分支报 `completed`，
在“重跑时无待下载记录”分支却报 `analyzing_completed`——状态取决于用户点了几次下载。**

### 真实数据印证

实例 `T20260830001`（心理学芳香正念，221 条通过 / 43 成功 / 178 失败）：

- `2026-08-30 18:43:22` 批量下载跑完 → 分支 5 → 写 `completed`（并存下 `completed_at`）
- `2026-09-02 09:44:40` 再次触发下载 → 无待下载记录 → 分支 4 → 打回 `analyzing_completed`

即 `completed_at` 至今残留但状态是「审核中」。修正后不会再出现这种自相矛盾。

## 3. 行为变更（需知悉）

**批量下载跑完但存在失败记录时，不再报「已完成」，而是留在 `analyzing_completed`
（页面「审核中」）并提示「部分记录下载失败，可在表格行级点“下载”按钮单独重试」。**

理由：

- 把「43 成功 / 178 失败」报成「已完成」本身是误导；
- 与分支 4 的既有意图一致——有失败就留在审核态，用户拿回重试入口；
- 不会造成无限重试循环：再次点「下载」会命中分支 4，立即返回并给出行级重试提示。

影响范围：**仅影响部署后新跑的批量下载任务**。实例状态是存量字段，不会被重算，
历史数据不受影响。

## 4. 统一后的判定（唯一入口）

```python
# app/services/download_progress.py
async def resolve_review_status(db, instance, stats=None) -> str:
    if not (instance.valid_data_count or 0):
        return "completed"                      # 无有效数据：无事可做
    if stats is None:
        stats = await get_download_progress_stats(db, instance.id)
    if stats["total"] > 0 and stats["success"] >= stats["total"]:
        return "completed"                      # 审核通过的已全部下载成功
    return "analyzing_completed"                # 待审核 / 部分失败待处理
```

签名由 `instance_id` 改为 `instance`（需要 `valid_data_count`），并支持传入已查好的
`stats` 以避免重复查询。`llm_worker` 两处调用点同步更新。

- `tests/test_review_status.py`：4 → **11 项**，其中 5 项覆盖 `download_worker`

- 反向验证：临时把批量分支退回「无条件 `completed`」，
  该用例确实失败，确认其真实守护本次行为变更。

  加两次新增共 17 项）一致，无回归。
