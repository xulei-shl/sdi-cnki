# 开发变更记录：普通检索模式改为专业检索式执行

- **日期**: 2026-08-03

## 1. 变更摘要

修复普通检索模式多关键词时导出结果超过「导出上限」的问题：此前普通检索模式对每个检索词**独立执行一次**高级检索，最终合并全部结果（N 个关键词 → N × 导出上限 条），导致最终入库条数远超用户设置的导出上限。

优化后，普通检索模式与专业检索模式统一走**专业检索（专业检索 Tab + 布尔表达式）**，只执行 **1 次**检索：

- 普通检索模式：将所有检索词合并为一条固定形式的检索式（检索词作为主题组 A），例如 3 个关键词 `阅读`、`远读`、`细读` 生成：

  ```text
  SU = (远读 + 细读 + 阅读) OR TKA = (远读 + 细读 + 阅读)
  ```

- 专业检索模式：保持不变（用户自定义主题 A/B + 作者/基金限定）。

由于只执行一次检索，**导出上限即为最终入库条数**，不再被关键词数量放大。

## 3. 说明

- 检索式中的关键词沿用专业检索模式现有的**单引号包裹**规则（如 `SU=('远读' + '细读' + '阅读')`），与既有专业检索实现一致，保证布尔表达式语法正确。
- 后端 `search_params` 数据结构不变：普通检索模式仍提交 `search_mode: "basic"` + `queries` 列表，仅执行阶段在 Worker 内转换，前端与历史模板无需改动。
- `tests/test_cnki_search.py` 直接调用 `CnkiInteractor`/`ProfessionalCnkiInteractor` 做交互器级验证，不受影响。
