### 1.2 问题清单

| # | 问题 | 严重度 | 违反原则 |
|---|------|--------|----------|
| P1 | **视觉权重扁平** — 4 个参数组外观一致，无法一眼区分「核心检索条件」与「辅助过滤条件」 | 高 | 层级通过多维度建立（size/weight/color/space），而非单一维度 |
| P2 | **纵向溢出** — 4 组垂直堆叠 + 3 个 AND 分隔线占据大量纵向空间，Dialog 内需要滚动 | 高 | 数据密集型 UI 需更紧凑的间距密度 |
| P3 | **节奏单调** — 4 个区块采用完全相同的 `space-y-3` 间距 + `space-y-5` 组间距，无疏密对比 | 中 | 间距应创造节奏：紧密分组 + 充裕间隔 |
| P4 | **语义断裂** — 主题 A/B 是一个逻辑整体（构成 SU 表达式），但被 AND 分隔线割裂；作者/基金是独立过滤条件，却与主题组视觉等权 | 高 | 空间分组应反映逻辑关系（邻近性原则） |
| P5 | **AND 分隔线噪音** — 3 条重复的 AND 分隔线消耗纵向空间，且信息密度极低 | 中 | 每个元素必须挣得自己的位置 |
| P6 | **布尔逻辑不直观** — 用户需要读完底部提示才能理解 A+B 的 AND 关系以及 AU/FU 的 AND 约束 | 中 | 好的布局即文档，空间关系应直接传达逻辑关系 |

### 1.3 Squint Test（眯眼测试）

眯眼审视当前布局：4 个区块模糊后形态完全一致，无法辨识主次。AND 分隔线化为 3 条等距横线，强化了"一切平等"的错误印象。

## 二、信息架构重构

### 2.1 语义分层

4 个参数组的逻辑关系并非扁平的 AND 链，而是两级结构：

```
┌──────────────────────────────────────────────────┐
│  主题表达式 (Topic Expression)                    │  ← 一级：定义"搜什么"
│  ┌────────────────┐  AND  ┌────────────────┐     │
│  │  主题A 关键词组  │       │  主题B 关键词组  │     │
│  │  SU=(A1+A2+…)   │       │  SU=(B1+B2+…)   │     │
│  └────────────────┘       └────────────────┘     │
└──────────────────────────────────────────────────┘
         AND
┌──────────────────────────────────────────────────┐
│  过滤条件 (Filters)                               │  ← 二级：缩小"搜多少"
│  ┌─────────────┐  AND  ┌─────────────┐           │
│  │  作者         │       │  基金         │           │
│  │  AU=(…+…)    │       │  FU % (…+…)  │           │
│  └─────────────┘       └─────────────┘           │
└──────────────────────────────────────────────────┘
```

**关键洞察**: 主题 A 与 B 构成对偶关系（共同决定检索表达式），作者与基金构成并列过滤关系。这两个层级应该通过空间分组清晰表达。

### 2.2 分组原则

| 维度 | 主题域 (A + B) | 过滤域 (AU + FU) |
|------|---------------|-----------------|
| 语义角色 | 定义检索范围的核心条件 | 缩小结果集的辅助约束 |
| 必填性 | 至少一组非空 | 均为可选 |
| 视觉权重 | **重** — 大面积、强调色 | **轻** — 紧凑、次级色 |
| 逻辑关系 | A AND B（对偶） | AU AND FU（并列） |

## 三、Dialog 宽度调整

### 3.1 现状

当前 Dialog 宽度为 `max-w-2xl`（672px）。单列布局下输入框宽度充足，但切换为双列后每列可用空间骤降：

### 3.2 宽度对比分析

| Dialog 宽度 | 内部可用* | 每列宽度** | 输入框宽*** | 评价 |
|-------------|----------|-----------|------------|------|
| 672px (`2xl`) | 624px | ~300px | ~264px | 偏窄，中文关键词输入局促 |
| **896px (`4xl`)** | **848px** | **~412px** | **~376px** | **舒适，输入区充裕** |
| 1024px (`5xl`) | 976px | ~476px | ~440px | 过宽，对话框占比过大 |

\* 内部可用 = Dialog 宽度 - 48px 左右 padding（DialogContent 默认 p-6）  
\** 每列宽度 = (内部可用 - 24px column gap) / 2  
\*** 输入框宽 = 每列宽度 - 28px 序号徽章 - 20px 删除按钮 - 16px 组内 gap

### 3.3 决策

**`max-w-2xl` → `max-w-4xl`**

理由：
- 双列布局下输入框需 ≥360px 才能舒适编辑中文关键词/基金名称
- `max-w-4xl` 单列降级时也不会显得空旷
- 与专业检索的信息密度匹配，避免"挤在窄框里"的局促感
- 普通检索模式（单列）同样受益于更宽的输入框

### 3.4 影响范围

需同步调整的文件：
- `src/pages/meta-task/dialog.tsx:269` — `max-w-2xl` → `max-w-4xl`
- `src/pages/task-instance/edit-dialog.tsx` — 同类 Dialog 同步调整

## 五、视觉层级强化策略

### 5.1 主题域 — 强调处理

- **边框**: 使用各组主题色作为左侧色带或整体淡色边框（`borderColor: var(--theme-a-bg)`）
- **标签字重**: `font-semibold`
- **标签色**: 继承 `--theme-a` / `--theme-b` 彩色
- **背景**: `bg-muted/20`，维持与表单整体的微弱区分
- **内边距**: `p-3.5`（14px），给予适度呼吸感

### 5.2 过滤域 — 弱化处理

- **边框**: 无边框（移除 `border`），或极淡边框 `border-border/50`
- **标签字重**: `font-medium`（降一级）
- **标签色**: `text-muted-foreground`（不使用强调色）
- **背景**: `bg-muted/10`（比主题域更透明）
- **内边距**: `p-3`（12px），更紧凑

### 5.3 AND 连接线 — 精简为 1 条

仅保留主题域与过滤域之间的 AND 分隔线。组内并列关系由网格布局的空间邻近性自然传达，无需显式标注。

### 5.4 间距节奏

遵循 DESIGN.md 的 4px/8px 律动：

```
--space-xs:  4px   // 组内元素间距（输入行之间）
--space-sm:  8px   // 标签与描述之间
--space-md: 12px   // 过滤域内边距
--space-lg: 14px   // 主题域内边距
--space-xl: 16px   // 网格行间距（主题域与过滤域之间）
```

**节奏**: 主题域内部紧凑（gap-2.5），域间宽松（gap-4），过滤域内部最紧凑（gap-2）。疏密交替创造视觉呼吸。

## 六、响应式降级

### 6.1 容器查询策略

当 Dialog 宽度不足时（移动端或窄侧边栏），双列自动降级为单列：

```css
.professional-search .grid {
  grid-template-columns: repeat(auto-fit, minmax(280px, 1fr));
}
```

或使用容器查询：

```css
.search-params-container {
  container-type: inline-size;
}

@container (max-width: 560px) {
  .topic-grid,
  .filter-grid {
    grid-template-columns: 1fr;
  }
}
```

### 6.2 降级顺序

| 容器宽度 | 布局 | 效果 |
|----------|------|------|
| ≥560px | 双列网格 | 主题A|B 并列，作者|基金 并列 |
| <560px | 单列堆叠 | 回退到当前垂直布局，但保留两级分组（主题域 + 过滤域） |

## 七、备选方案对比

### 方案 B: 主次分栏

```
┌──────────────────────────┬──────────────┐
│  主题A 关键词组            │  作者（可选）  │
│  ┌─ input ── input ─┐   │  ┌─ input ─┐ │
│  └──────────────────┘   │  └─────────┘ │
│                          │              │
│  主题B 关键词组            │  基金（可选）  │
│  ┌─ input ── input ─┐   │  ┌─ input ─┐ │
│  └──────────────────┘   │  └─────────┘ │
│                          │              │
└──────────────────────────┴──────────────┘
         7:3 比例
```

**优点**: 主次关系最直观，主题域占主列，过滤域占侧栏  
**缺点**: 侧栏空间局促，关键词数量多时输入框过窄；响应式降级复杂  
**评价**: 适合查看页，不适合编辑页（输入框宽度受限）

### 方案 C: 折叠面板

```
▼ 主题表达式（必填）
    [主题A] [主题B]  并列输入

▶ 过滤条件（可选）     ← 默认折叠，点击展开
    [作者] [基金]
```

**优点**: 最紧凑，过滤域默认隐藏  
**缺点**: 隐藏了可选但重要的信息，增加交互步骤；对首次使用的用户不友好  
**评价**: 适合高级用户模式，V1 不推荐

### 方案选型结论

**推荐方案（双行双列网格）** 在信息密度、层级表达、编辑体验三者间取得最佳平衡：

| 评估维度 | 推荐方案 | 方案 B | 方案 C |
|----------|---------|--------|--------|
| 纵向压缩 | ★★★★ | ★★★★★ | ★★★★★ |
| 层级表达 | ★★★★★ | ★★★★ | ★★★ |
| 编辑体验 | ★★★★★ | ★★★ | ★★ |
| 响应式 | ★★★★ | ★★ | ★★★ |
| 实现成本 | ★★★★★ | ★★★ | ★★ |

## 八、检索逻辑提示优化

### 8.1 当前文案

```
检索逻辑：(SU=A×B) OR (TKA=A×B)，每组内关键词用 OR 连接，两组间用 AND 连接，作者条件用 AND 连接，基金条件用 AND 连接
```

### 8.2 优化文案

利用布局本身传达逻辑后，提示文案可精简：

```
表达式：(SU=A×B) OR (TKA=A×B)   ·   组内 OR · 组间 AND
```

过滤条件的 AND 关系已由 AND 分隔线和视觉层级传达，无需文字赘述。动态部分（有作者时追加 `AND AU=(…)` 等）保留，但合并为一行紧凑展示。
